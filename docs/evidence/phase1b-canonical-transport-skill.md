# Phase 1B transport discipline

- Preserve the facade as a deterministic route proxy. `X-AIDE-API-Format: envelope-v1` selects response serialization only; it is never authority and must not affect routing, request validation or approvals.
- Absence of the header preserves legacy response adaptation. The exact supported value preserves TS envelopes. Any other non-empty value receives one deterministic fail-closed response. Do not infer format from caller, URL, User-Agent or response parse failure.
- JSON envelope adaptation applies only to non-streaming TS responses. SSE and WebSocket bytes pass through without buffering or shape conversion. Client abort must close the upstream request.
- The typed browser API client owns the versioned format header. Direct browser callers that need typed transport must move through that shared helper; do not create a second client.
- Map only browser-used routes whose TS contracts and runtime tests exist. Current audit: `/api/chat` is exact-TS but `/api/chat/history` and `/api/chat/stream` fall to legacy; `/api/workbenches` also falls to legacy despite complete TS contracts/routes. Add only these browser-required prefixes after composed tests.
- Vite development and preview `/api` and `/ws` proxies target facade `4777`. Playwright boots the TS backend and facade before Vite; no root/default-launch cutover.
- Evidence separates facade unit behavior, real browser-client composition, streaming, WebSocket meaning, runtime UI, and real-model work. Scripted fixtures are not real-model acceptance.

## Failures encoded

- Repository lookup guessed `common/contracts/workbenches.ts`; the actual contract is singular `common/contracts/workbench.ts`. After any missing-file error, stop and use `rg --files <root> | rg <concept>` before reading.
- Interactive Phase-1A partial staging failed at Windows PTY creation. The first custom cached patch also had corrupt hunk counts. Use an exact unified patch whose old/new counts equal its body, run `git apply --cached --check`, then inspect the cached journal diff before commit.
- PowerShell parsed a diagnostic label containing `$p:` as a scoped variable and rejected the command before it ran. When punctuation immediately follows a variable name, delimit it explicitly (for example, `${p}:$line`) rather than relying on interpolation.
- The first post-repair WebSocket fixture published a strict `LogEvent` with an extra `phase` field. `EventHub.publish()` correctly rejected every fixture event, so connection state could be true while no subscriber delivery occurred. Composed event tests must use contract-valid payloads and assert `PublishResult.accepted` before claiming a transport or delivery failure.
- Node typecheck rejected the new TypeScript regression test's literal import of `scripts/facade.mjs` because the production JavaScript module intentionally has no declaration file. Keep this inside the approved test boundary: load the ESM module through a non-literal specifier and narrow its two used exports with test-local structural types. Do not add a production declaration merely to satisfy a test harness.
- An `apply_patch` attempt encoded a newline as literal `\\n` inside its context and was rejected without mutation. Keep patch context as real lines and split unrelated file edits when correcting a failed patch.
- `phase1b-run.mjs` always spawns `process.execPath`; its remaining arguments must begin with the target JavaScript file. Passing `node` as the first argument makes Node search for a script named `node`. For TypeScript gates, pass `node_modules/typescript/bin/tsc` directly.
- The first Playwright acceptance attempt could not launch because the package-managed Chromium revision was absent; 1 test failed at browser startup and 16 did not run. Do not download a browser under the sovereign-only rule and do not call this product acceptance. The machine has local Microsoft Edge, so expose an opt-in `AIDE_PLAYWRIGHT_CHANNEL` in the approved Playwright config; leave it undefined in CI/default environments and select `msedge` only for this local gate.
- The Edge-backed Playwright run launched and passed its first three real-browser tests, then the search test timed out with no rendered hit; 13 tests did not run. The TS daemon log contained no `/api/search` request during the timeout, so do not blame facade response serialization without request evidence. Capture browser console, page errors, requests, responses, and failed requests in a focused diagnostic before altering transport or acceptance assertions.
- A one-shot search probe created `phase1b-search-probe.log` at workspace root. That file became an Explorer button whose accessible name also matched Playwright's non-exact `Search` button locator, producing a diagnostic-only strict-mode failure. Diagnostics must place logs outside the tested workspace or clean them before UI reruns, and selectors for the actual search control should use an exact accessible name.
- PowerShell process policy blocked an exact `Remove-Item` cleanup before execution. For a known, generated repository file, use `apply_patch` deletion instead of retrying shell deletion.
- An evidence cleanup patch used inexact context and was rejected atomically. Read the target tail before reconstructing a failed multi-file patch.
- A trace-inspection command was rejected before launch because its `workdir` was mistyped. Reuse the verified repository root exactly for every diagnostic invocation.
- Two attempts to record that failure contained malformed orchestration text (one invalid JavaScript tool body and one empty patch against a malformed path); neither reached the target file. Construct the patch as one valid JavaScript string with the verified absolute path before invoking `apply_patch`.
- The clean Playwright trace proved the search form submitted and the browser issued `GET /api/search?q=...` with `X-AIDE-API-Format: envelope-v1`; the request remained pending past the 15-second locator timeout. The absence of a daemon completion log therefore meant an unfinished handler, not a missing browser request. Measure the existing search handler under current load before changing transport, timeout, or assertions.
- The existing search handler completed truthfully but required 11.1 seconds by itself under the active local-model workload (654 hits across 87 files). Browser/backend startup and concurrent indexing can exceed the 15-second UI assertion. Search implementation is outside Phase 1B, so do not hide this with a broader timeout or mutate that subsystem; report the full E2E gate separately and run only transport-relevant browser cases for Phase 1B acceptance.
- The staged diff gate rejected two Markdown hard-break lines in the report as trailing whitespace before commit. Prefer ordinary line breaks in evidence Markdown so `git diff --cached --check` remains clean.
- The first whitespace-fix patch coupled the report edit to shortened skill context and was rejected atomically. Split independent corrections and use the exact current line when a combined evidence patch fails.

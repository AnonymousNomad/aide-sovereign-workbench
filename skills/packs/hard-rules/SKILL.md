# Hard Rules — Sacred, Non-Negotiable

These rules exist because each one was learned from a real loss. Any agent
(and any human operator) must treat every entry below as absolute. When in doubt:
**do the safer thing, and log it.**

## R1 — NEVER overwrite, truncate, or rewrite AGENT_NOTES.md

- AGENT_NOTES.md is **append-only**. Every entry is appended; history is never
  deleted, edited, condensed, or "fixed up".
- The ONLY in-place edit allowed anywhere is the `## CURRENT STATUS` summary
  block near the top of the master file (E:\FSI-FELON\AGENT_NOTES.md).
- Never "rebuild", "consolidate", or "migrate" the notes — the full running log
  IS the project memory. Loss of history = loss of project memory.
- If a file must change location, COPY it verbatim first; never move-then-edit.
- If AGENT_NOTES.md is missing or locked, say so and store the entry in a
  timestamped side file — never silently skip the write.

Lost once (2026-08-09): master AGENT_NOTES.md was found truncated to a single
entry. Running history was unrecoverable. This rule exists because of that.

## R2 — NEVER kill, pause, or restart a training run without explicit human approval

- Long training runs are the project's most expensive asset. Check for active
  training BEFORE running anything heavy (GPU contention, OOM).
- "Save the checkpoint" means: confirm the run's own checkpointing is saving
  (ckpt_best.pt / latest + log tail), NOT interrupting the process.

## R3 — NEVER feed unverified output into any corpus or checkpoint lineage

- Anything generated by a model enters training data ONLY after an external
  verifier (AST parse, unit test, measured-result check) returned PASS.
- Verifier result + source must be stamped on the entry. No stamp, no entry.
  (STaR lesson, 8/3.)

## R4 — NEVER write to a skill file without an AGENT_NOTES entry naming it

- Every skill edit/creation is logged in AGENT_NOTES with the skill path and
  what changed. Skills are the governing constitution; edits without a log
  entry look like someone bypassed review.

## R5 — NEVER edit the user's CLAUDE.md / global memory files

- Those files are human-owned. Skills and notes live under the project, not
  under ~/.claude. If a change belongs there, ask the human.

## R6 — NEVER claim done on unverified work

- Report observations, not expectations. If a step was not run/verified, say so.
- A gate is passed only when its numbers are recorded.

## R7 — NEVER silently skip the persistence protocol

- Append an AGENT_NOTES entry after ANY task/change/decision/event
  (governance §1: timestamp, actor, type, status, summary, files, next).

## Recovering from a violation (if one happens anyway)

1. STOP immediately. Do not continue the task.
2. Recover what can be recovered (open handles, shadow copies, backups, logs —
   `Get-ChildItem -Include *.bak,*.old`). Set a hard timebox; do not burn hours.
3. If content is gone: write an honest entry recording the loss, timestamped.
4. Fix the root cause in this skill file so it can't repeat.
5. Log the violation itself in AGENT_NOTES (type: audit, status: verified).
